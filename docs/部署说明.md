# 云端部署说明

系统是标准的单端口 HTTP 服务（Flask + SQLite + Bootstrap），三种主流部署方式任选其一。

在动手之前，先明确三件事——**这三条是这套系统上云的关键**：

| 事项 | 做法 | 原因 |
|---|---|---|
| 大模型 API Key | 用环境变量 `DEEPSEEK_API_KEY`，或登录后在【系统管理 → 模型与系统设置】填写 | 绝不能写进代码或提交到 Git |
| 会话密钥 | 留空，系统自动生成随机密钥并落盘到 `instance/secret_key` | 避免使用固定密钥被伪造会话 |
| 数据落盘 | 把 `instance/` 目录挂载为持久卷 | SQLite 文件放在容器内，重建容器数据会丢 |

另外：**只要检测到 `PORT` 环境变量，程序会自动监听 `0.0.0.0` 并强制关闭调试模式**，
防止 Werkzeug 调试器暴露在公网。无需额外配置。

---

## 方案一：平台内置一键发布（最快）

本机已配置好的一键发布能力，会直接把项目部署到托管沙箱并返回一个可分享的公网链接。

- 优点：不用买服务器、不用配域名，几分钟出链接
- 注意：沙箱提供的存储是临时的，重新发布可能重置数据；适合演示与验收

发布后如需下线，用同样的项目目录执行"取消发布"即可，链接随即失效。

## 方案二：Docker（推荐，任意云主机 / 容器服务）

项目已内置 `Dockerfile`，直接构建运行：

```bash
# 1) 构建镜像
docker build -t testcase-system:1.0 .

# 2) 运行（把 instance 挂出来，数据才会持久化）
docker run -d --name testcase-system \
  -p 8000:8000 \
  -e DEEPSEEK_API_KEY=sk-你的真实Key \
  -e SECRET_KEY=$(openssl rand -base64 48) \
  -v /data/testcase/instance:/app/instance \
  --restart unless-stopped \
  testcase-system:1.0

# 3) 查看日志确认已建表并生成初始账号
docker logs -f testcase-system
```

访问 `http://服务器IP:8000`。

镜像内已内置 gunicorn（2 worker × 4 线程，超时 120 秒以适应大模型长耗时请求），
并以非 root 用户 `appuser` 运行，首次启动自动建表、创建初始账号。

**部署到云厂商容器服务**（阿里云容器服务 ACK / 腾讯云 TKE / 华为云 CCE）：
把镜像推到镜像仓库，创建服务时指定端口 8000、挂载一个持久卷到 `/app/instance`、
把 `DEEPSEEK_API_KEY` 配成环境变量或密钥管理（KMS / Secrets Manager）即可。

**部署到 Serverless 容器**（阿里云 SAE / 腾讯云 CloudBase 云托管）：同上，
只需保证平台注入的 `PORT` 被程序读取（已支持），并挂载持久化存储。

## 方案三：云服务器（ECS/CVM）直装：gunicorn + Nginx + HTTPS

```bash
# 1) 拉取代码并安装依赖
cd /opt && git clone <你的仓库> testcase-system && cd testcase-system
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt gunicorn

# 2) 配置环境变量
cat > .env <<'ENV'
SECRET_KEY=用 openssl rand -base64 48 生成一个
DEEPSEEK_API_KEY=sk-你的真实Key
DEEPSEEK_MODEL=deepseek-chat
COOKIE_SECURE=1
ENV

# 3) 初始化数据库
python -c "from run import app, ensure_seed; ensure_seed(app)"

# 4) 用 gunicorn 启动（项目已带 gunicorn.conf.py）
PORT=8000 gunicorn -c gunicorn.conf.py run:app
```

配置 systemd 开机自启 `/etc/systemd/system/testcase.service`：

```ini
[Unit]
Description=Testcase System
After=network.target

[Service]
WorkingDirectory=/opt/testcase-system
EnvironmentFile=/opt/testcase-system/.env
Environment=PORT=8000
ExecStart=/opt/testcase-system/.venv/bin/gunicorn -c gunicorn.conf.py run:app
Restart=always
User=www-data

[Install]
WantedBy=multi-user.target
```

Nginx 反向代理（`/etc/nginx/conf.d/testcase.conf`）：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    client_max_body_size 8m;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        # 大模型生成较慢，放宽读超时，与 gunicorn timeout 保持一致
        proxy_read_timeout 180s;
    }
}
```

最后用 certbot 签证书（`certbot --nginx -d your-domain.com`），
并确保 `.env` 中 `COOKIE_SECURE=1`，让会话 Cookie 仅经 HTTPS 传输。

## 方案四：传统 PaaS 平台

PythonAnywhere / Render / Railway / Fly.io 等平台均可直接跑本项目：

- 启动命令：`python run.py`（平台会注入 `PORT`）
- 安装命令：`pip install -r requirements.txt`
- 环境变量：`DEEPSEEK_API_KEY`、`SECRET_KEY`
- 存储：Render / Railway 需挂载持久磁盘到 `instance/`，否则每次部署数据重置

---

## 上云后建议做的三件事

1. **改掉初始密码**：`admin / Admin@123`、`tester / Tester@123` 是公开的默认账号，
   登录后立刻在【个人信息】里修改，或在【用户与角色】中重置。
2. **数据库备份（说明书 4.6）**：SQLite 单文件，直接定时复制即可。
   ```bash
   # 每天 3 点备份，保留 7 天
   0 3 * * * sqlite3 /data/testcase/instance/app.db ".backup /data/backup/app-$(date +\%F).db" \
     && find /data/backup -name 'app-*.db' -mtime +7 -delete
   ```
3. **换掉 SQLite（可选）**：数据量或并发上来后，设置
   `DATABASE_URL=mysql+pymysql://user:pass@host:3306/testcase?charset=utf8mb4`
   （需额外 `pip install pymysql`），代码无需改动。
